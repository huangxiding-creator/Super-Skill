## Top 8 mechanisms to adopt (with specifics)

### 1. A real fitness function: a "skill-bench" plus the autoresearch keep/discard loop (autoresearch + DGM)
- Add `evolver/bench/` with 10-30 small fixed tasks (e.g. "idea to scaffolded CLI with passing tests"). Each task has a deterministic grader: tests pass, lint is clean, verification-gate checklist score, tokens used, wall time.
- Fitness = `pass_rate − λ·(tokens/1e5) − μ·(SKILL.md added lines/100)`. The size penalty is the autoresearch simplicity criterion.
- Loop: branch `evolve/<tag>`, mutate one SKILL.md or gene, run the bench under a fixed budget, append a row to `evolver/results.tsv` (`commit score tokens status desc`, status ∈ keep/discard/crash), then fast-forward if better or `git reset --hard` if not. Kill any run over 2x the budget.
- **Staged evaluation (DGM):** run a 3-task smoke subset first. Run the full bench only if the smoke score is at least the second-best archive score.

### 2. DGM archive with `score_child_prop` parent selection (darwin-evolution/selector.js)
- `evolver/archive.jsonl`: `{id, parent, commit, score, children, resolved_ids, unresolved_ids}`.
- Parent weight = `sigmoid(10*(score-0.5)) / (1+children)`, sampled with `random.choices`.
- Keep all variants, not just the best, so stepping stones survive. Admit a variant with `keep_better` at a 0.1 noise leeway.
- Mutation prompt: "here is the parent skill plus the bench tasks it failed plus their logs; propose one change."

### 3. GEPA reflective mutation plus a Pareto frontier over bench tasks
- Instead of a single best variant, keep every variant that is best on at least one task (the Pareto front). Sample parents from the front.
- The evaluator returns ASI, meaning the error text, failing test and phase that stalled. The reflection LM reads the ASI and writes a targeted edit to one SKILL.md section.
- Optional *system-aware merge* of two front members that win on different tasks.
- MIT, and gepa already ships `.claude/skills/gepa-optimize-anything/`. The fastest path is to wrap `optimize_anything(seed=SKILL.md section, evaluator=bench runner)`.

### 4. ACE playbook with helpful/harmful counters to replace the prose cerebrum
- Convert the cerebrum Do-Not-Repeat list to `cerebrum/playbook.jsonl` bullets: `{id, section, text, helpful:n, harmful:n, created_run, last_used_run}`.
- After each run, the Reflector tags which bullets were used and whether they helped. The Curator emits **delta ops only** (`ADD`, `UPDATE id`, `+helpful id`, `+harmful id`) and **never rewrites** the file. This avoids context collapse.
- Dedup by embedding or BM25 similarity above 0.9. Prune when `harmful > helpful+2`, and enforce a token budget by evicting the lowest (helpful − harmful).
- ExpeL's UPVOTE/DOWNVOTE semantics are the same idea. Graphiti adds *invalidate, not delete*: set `superseded_by` so history stays auditable.

### 5. Retrieval over markdown memory: claude-mem 3-layer disclosure plus mem0 fused retrieval (memory-pipeline)
- Keep Markdown as the source of truth (the basic-memory philosophy). Build a SQLite FTS5 index (`scripts/memindex.js` using `better-sqlite3`, or `node:sqlite` on Node 22+). Embeddings are optional.
- Query API has three layers: `search(q)` returns IDs, titles and 1-line summaries (about 60 tokens each); `timeline(id)` returns neighbours by time; `get(ids)` returns full text.
- Rank by fused score = RRF(BM25, embedding cosine, entity or tag overlap) plus a recency boost (mem0 v3 multi-signal plus temporal).
- Write path is ADD-only with provenance (run id, phase), matching mem0 v3 and graphiti episodes.

### 6. Voyager skill library for the 50+ sub-skills (anatomy-scanner / find-skills / pre-run-upgrade)
- For each sub-skill, store an LLM-generated 2-3 sentence description plus an embedding (or a BM25 fallback). `retrieve_skills(phase_goal, k=5)` loads only the relevant SKILL.md files rather than all of them, which saves tokens.
- New skills or genes enter the library **only after self-verification**: bench or verification-gate pass. That is Voyager's critic gate.

### 7. Aider-style ranked repo map with a token budget (anatomy-scanner, context-compressor)
- Replace the flat file index with tree-sitter definition and reference tags. Build a file graph and run personalized PageRank, seeded by files and identifiers mentioned in the current phase.
- Binary-search how many ranked symbols fit in `map_tokens` (1024-4096).
- Use `repomix --compress` for one-shot whole-repo packing with token counts, and serena's `find_symbol` / `find_referencing_symbols` over MCP for precise edits.
- Aider's code is Apache-2.0, so the algorithm can be ported directly.

### 8. GEP hardening from evolver: presets, stagnation detection, mutation object, git solidify (fills the empty `evolver/`)
- `EVOLVE_STRATEGY=balanced|innovate|harden|repair-only` sets the mix of mutation types, e.g. innovate 60/20/20 versus repair-only 0/0/100.
- Every cycle writes an explicit Mutation record to `events.jsonl`: `{gene_id, intent, target_files, expected_signal, blast_radius}`.
- **Signal de-dup**: if the same signal or gene pair fires N times without the score improving, mark it stagnant and force a different gene or escalate. This prevents repair loops.
- **Solidify** only after the bench passes (commit plus event). Otherwise roll back via git.
- Evolver is GPL-3.0 and moving to source-available, so **clean-room re-implement**. Do not copy the code into Super-Skill.

### Honourable mentions
- agent-lightning's span and reward schema for `events.jsonl`, so the same traces could later feed RL or APO.
- OpenEvolve MAP-Elites cells (e.g. axes = skill length × phase coverage) for diversity once the archive grows.
- ShinkaEvolve UCB bandit over which LLM performs mutations, for cost control.
- Letta size-limited core memory blocks for an always-loaded `MEMORY.md` header.
- LLMLingua-2 for compressing retrieved memories.
