## 2. Top 8 mechanisms to adopt (with specifics)

### M1. Executable phase gates: goose `retry.checks` + SWE-agent multi-stage submit
- **Fixes:** "verification is checklist prose".
- **Specifics:**
  - Every phase in `SKILL.md` gets a YAML block: `gate: {checks: [{type: shell, command: "pytest -q"}, {type: shell, command: "python scripts/validate_prd.py docs/prd.json"}], max_retries: 3, on_failure: "..."}`.
  - A new `scripts/run_gate.py` runs the checks. Exit code 0 is required to advance.
  - On failure it resets the phase context and retries (goose semantics).
  - Add a submit gate: the first "phase done" call prints the diff/artifact plus a review checklist, and only a second confirmed call advances. This mirrors `tools/review_on_submit_m/bin/submit` with `SUBMIT_STAGE`.
- **Source:** goose `recipe-reference.md#retry` (Apache-2.0); SWE-agent `tools/review_on_submit_m` (MIT).

### M2. A real loop engine: vendor mini-swe-agent's `DefaultAgent`
- **Fixes:** "no real runtime".
- **Specifics:**
  - Copy `src/minisweagent/agents/default.py` (MIT). It gives step, cost and wall-time limits, a format-error limit, an exit-role termination and a trajectory saved after every step.
  - Use it as `scripts/loop_runner.py` for P9. Its stateless per-command subprocess env can be swapped for docker via SWE-ReX.
- **Payoff:** P9 becomes runnable and budget-bounded instead of prose.

### M3. Ralph loop as a script: snarktank/ralph
- **Specifics:**
  - Vendor `ralph.sh` plus the `prd.json` schema (`userStories[{id, priority, passes, acceptance}]`, `branchName`) and `progress.txt`. All MIT.
  - Each iteration runs `claude -p` in a fresh context, handles one story, runs quality checks, commits only on green, and flips `passes: true`.
  - P7 WBS emits `prd.json` directly.
- **Payoff:** P11 becomes resumable, and its state lives in git rather than in the context window.

### M4. Cheap rollback for experiments: gemini-cli shadow-git checkpoints + Plandex branches
- **Specifics:**
  - Before each experiment in P9, commit into a shadow repo: `git --git-dir=~/.super-skill/history/<hash> --work-tree=. add -A && commit`.
  - Keep or discard each experiment autoresearch-style with `/restore`.
  - Plandex-style branches let the loop compare alternative approaches or models on the same step.
- **Source:** gemini-cli `docs/cli/checkpointing.md`.

### M5. Candidate sampling plus test-based selection: Agentless + trae-agent Selector
- **Specifics:**
  - For risky tasks in P9/P11, sample N=3-5 patches.
  - Generate a reproduction test (`generate_reproduction_tests.py`) and select regression tests (`select_regression_tests.py`).
  - Discard any patch with a non-empty `regression` field, then rerank the rest by majority vote plus reproduction pass (`repair/rerank.py`).
  - Optionally have an LLM chooser, as in SWE-agent `ChooserRetryLoop`.
- **License:** all MIT.

### M6. Stuck detection and critic-driven refinement: OpenHands SDK
- **Specifics:**
  - Port `conversation/stuck_detector.py` (MIT). It scans the last 20 events for 4 patterns: repeated action and observation, repeated action and error, monologue, and A-B alternation.
  - Wire it into Ralph and P9 so a stuck loop triggers a strategy change or escalation instead of burning budget.
  - Add a critic step after each phase. `should_refine(result)` decides whether to send one bounded follow-up (`IterativeRefinementConfig`).
  - Adopt the condenser rule for long runs: summarize the older half into a tombstone event and keep the recent half verbatim.

### M7. Aider repo map for GitHub discovery and the KB
- **Specifics:**
  - Vendor `aider/repomap.py` (Apache-2.0, keep NOTICE) as `scripts/repo_map.py`.
  - It extracts tree-sitter def/ref tags, builds a file graph and runs personalized PageRank with extra weight on the files and identifiers mentioned in the task. The output is binary-searched to fit the token budget.
  - Use it in P3 to summarize candidate repos in ~1-2k tokens each, and in P9 as the context for each step.
