# Radar 2026-10-07 — V5.1.4

**Summary:** 堵住第三方 skill 安装前审查的漏洞：可执行文件、编译产物、无法检查的压缩包和指向技能目录外的符号链接不再被静默判为 CLEAN；Judge 新增 Worker 没见过的额外检查（HOLDOUT），防止只针对自己的测试凑通过。

## Adopted
- **NVIDIA/SkillSpector** — 无法检查的内容（二进制、压缩包）要报告、不得静默跳过；按内容而非扩展名白名单分类，新增 BIN1/BIN2/LNK1 规则 → `engine/skill_vet.py, engine/tests/test_skill_vet_opaque.py` (Apache-2.0, pattern)
- **Q00/ouroboros** — 评分用的检查不交给执行方：Judge 根据需求验收标准自建一个 Worker 没见过的额外检查，与验证命令都通过才判 KEEP → `agents/ss-judge.md` (MIT, pattern)

## Files changed
- `engine/skill_vet.py` — Close a fail-open gap in pre-install skill vetting: files outside the text-extension allowlist were silently skipped, so a skill shipping helper.exe, a .pyc, a .vbs, an ELF renamed to logo.png or a symlink to ~/.ssh scored CLEAN. Now classified by content: BIN1 (executable/compiled, high), BIN2 (opaque binary/archive, medium), LNK1 (symlink escaping the bundle, high); text files with any extension are scanned. Existing rules, bounds, score and CLI unchanged.
- `engine/tests/test_skill_vet_opaque.py` — Tests for BIN1/BIN2/LNK1, disguised executables via magic bytes, unlisted text extensions now scanned, inert media/docs and 'MZ'-prefixed text stay clean, --ignore suppression and CLI exit code.
- `agents/ss-judge.md` — Judge must run at least one held-out probe derived from the REQ acceptance text (never from the worker's tests) and report it as a HOLDOUT evidence line; KEEP requires both verify and holdout to pass. Counters teaching-to-the-test by workers.
