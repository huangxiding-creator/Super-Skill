# PAI-Station 开发宪法（全局适配版）

> 来源：PAI-Station 项目（提案 V1.0→V3.2 全过程，2026-09）沉淀提炼。原则均以通用形式表述，适用于一切项目；PAI-Station 章节号为出处索引（提案第 17/18/19/20/21 章）。
> 加载时机：任何项目的方案设计、选型、排期、交付、复盘环节；与 `audit-loop-case-study.md`（过程方法论）互补，本文件是**价值论与方法论的裁决层**。

## 十二条开发原则

1. **站在巨人肩膀**：绝不重新发明。任何自研点先调研 ≥10 个开源/成熟项目（全附官方链接），输出"对比表+选型结论+缝合什么/怎么改造"三栏（PAI-Station 19 章 46 项、18 章 22 项吸收矩阵为范式）。
2. **最难优先**：难度=价值=护城河。简单域各家同时进化、筑不了壁垒；资源冲突时按**价值密度 = 难度 × 用户痛度 ÷ 竞品可抄度**裁决，最高者胜（20 章）。
3. **巨人肩上再攻坚**："容易的事借巨人的肩，最难的事也是在巨人的肩基础上再自己扛"——难点也先找巨人地基（标准/基建/先例），绝不从零硬扛；巨人没造过的攻坚段必须自己扛（20.1，用户 2026-09-07 精炼）。
4. **100× 升维**：把用户想法做成"升维对照表"（用户原话要点 → 升维方案 → 倍增机制），逐要素落进工程方案，并补上用户没提但决定成败的东西（19.0 十三行对照表为范式）。
5. **软承诺硬化**：一切"最好/尽量/永久/绝对"改写为可证伪承诺——验收线数字、触发器、最低可用降级形态（16 章 Q12 三例为范式）。
6. **借鉴成熟做法，不自造环境方案**：遇到 git push/下载/编码/通知等本地环境问题，先读本地其它成功项目的配置与脚本（它们能跑通=已验证），照抄配方；不要自己发明重试循环或代理配置（实测案例：照抄 We-AIPO 的全局 git 配方而非自设 repo 级 proxy）。
7. **红队常态化**：每版方案过三重角色质询（投资人/安全研究员/交付者），质疑→充分调研→解法融入正文并编号落章节（16 章 13 问为范式）。
8. **用户主权公理**："一切皆有默认、无一被锁死"；每个配置面字段最小化（每源 6 字段原则，"没必要的不搞"）；**opt-in 铁律**——默认最小，升级必须用户确认，任何"默认开启再让用户关"违宪（17/21 章，Microsoft Recall 反例）。
9. **信任先于能力**：先信任后采集（Recall 是先采集后信任的逆序失败样本）；信任要资产化：账本+预算+渐进阶梯+事故修复协议（21 章）。
10. **密钥红线**：密钥只存 gitignored 的 secret.ini（或环境变量/凭据管理器），永不进仓库、永不全文打印；每次交付前全库密钥扫描并输出"零命中"证据。
11. **交付即通知**：每个里程碑双通道通知（文字摘要+文件产物）；通道故障时挂自动重试值守+成功即通知，绝不静默失败。
12. **排期可证伪**：里程碑必须含 Kill 指标与收缩分支（M0.5 假设检验门范式）；里程碑评审**先审难点进度**，再谈其余（难度审计）。

## 开发最讨厌（发现立刻叫停）

- **无调研断言**：说"最优/第一/超越竞品"但拿不出 ≥10 项对比表。
- **重新发明轮子**：成熟开源或成熟项目已有解，自己手搓。
- **自造环境方案**：本地坑（push/代理/编码/通知）不查成熟项目配方就发明自己的做法。
- **容易事项凑里程碑**：用低价值交付物稀释难点攻坚——hard 工时占比 ≥40% 是保护线，连续两周不达即砍容易事项让位（20.4）。
- **软承诺**：口号式"永久免费/绝对安全/一定好用"，无验收线无证伪路径。
- **默认全开**：任何感知/采集/外发默认开启，等用户来关。
- **配置蔓延**：一个功能二十个字段，吓退普通用户。
- **密钥/敏感信息**进仓库、进日志、进对话输出。
- **静态交付物**：技能/方案/文档只有第一版没有生命周期（无进化、无血缘、无衰减检测）。
- **报喜不报忧**：测试失败说成通过、推送失败不说、跳过的步骤不交代。

## 开发宪法（冲突裁决序）

```
安全与信任 > 最难优先 > 巨人肩膀 > 用户主权 > 交付速度
```

遇到原则冲突按此序裁决，每次裁决在 ADR 记一行（何冲突、何取舍、为何）。安全与信任永远第一：它们崩一次，其余全部归零（信任账本思维）。

## 配套机制（宪法不空转）

| 机制 | 内容 | 出处 |
|---|---|---|
| 难度治理 | 里程碑难度审计/hard 工时 ≥40%/攻坚日志/失败预算 30%/价值密度公式 | 20.4 |
| 检验门 | 每个大里程碑前设假设检验子门，Kill 指标不达标触发收缩分支 | 16.7 |
| 信任四件套 | 账本/预算/阶梯/修复协议，月度信任报告 | 21.2 |
| 吸收债务清零 | 竞品/参考项目新特性 7 日内评估、季度刷新对比表 | 18.5 |
| 密钥扫描 | 交付前全库扫描密钥指纹，"零命中"写进交付清单 | 本项目交付 SOP |
